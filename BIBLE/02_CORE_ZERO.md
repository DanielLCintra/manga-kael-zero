# KAEL ZERO — CORE ZERO & Sistema de Evolução

## O que o CORE é

**CORE ZERO** = IA + plataforma de assemblagem molecular / informacional.  
Função: transformar **informação digital + intenção estruturada** em **matéria física coerente**.

Não concede poderes mágicos.  
Funciona como **sistema operacional vivo** acoplado ao organismo de Kael (após sincronização).

### Analogia interna (para o roteiro, não aula pro leitor)
Kael = processador biológico anômalo + fonte energética.  
CORE = compilador / runtime / sandbox / **biblioteca de projetos**.  
Blueprint = código-fonte.  
Materialização = build / instantiate.  
Energia Hélice = eletricidade + banda de I/O.  
Construct = processo em execução (pode ser mantido, pausado, deletado).

## Matéria de Fase Hélice (visual + física)

Nome interno: **Helix-Phase Matter** / **Matéria Hélice**.

### O que é
Estado coerente em que massa, dureza, momento e forma são sustentados por uma **rede informacional** (lattice) gerada pelo CORE + canal Hélice.

- **É física:** corta, bloqueia, pesa, quebra, conduz calor, faz barulho ao bater  
- **Parece digital:** translúcida teal/ciano, circuit-glass, wireframe residual, brilho clínico — **aura digital permanente** nos constructs maduros  
- **Não é magia:** ORION pode detectar assinatura espectral; sensores veem “anomalia de fase”

### Por que não “vira metal normal”
Adrian descobriu (notas tardias): a fase Hélice é **mais estável para o CORE** do que matéria mundana plena.  
Forçar render 100% “opaco/normal” custa mais e falha mais (ver parafuso #1 @ 84%).

| Nível de domínio | Aparência típica | Notas |
|------------------|------------------|-------|
| Iniciante (T1) | Quase sólido mundano, opaco, falhas | Parafuso; ferramentas |
| Intermediário | Híbrido: sólido + veios digitais | Defesa / armas sob coerção |
| Avançado | Aura digital plena, ainda física | Look das refs com CORE |
| Máster | Constructs complexos sustentados; biblioteca viva | “Qualquer coisa” *modelável* |

### Manutenção
Constructs avançados podem exigir **custo contínuo** enquanto existirem (hold).  
Soltar o hold → dissolvem em vapor informacional / poeira de fase (SFX visual característico).  
Blueprints salvos **não** custam energia — só a instanciação.

## Dois modos de criação

### 1) Soft Compile — “pelo pensamento”
- Forma simples, familiar, baixa complexidade  
- Intenção + modelo mental rápido  
- Rápido, barato, frágil, curta duração  
- Exemplos: placa, haste, gancho, parafuso, escudo bruto, lâmina simples  

### 2) Hard Compile — “projeto programado”
- Objeto completo / arma / dispositivo / estrutura  
- Exige **projeto** (desenho, estudo, engenharia, engenharia reversa, simulação)  
- Kael **grava o blueprint na Biblioteca do CORE**  
- Depois: `LOAD → COMPILE → HOLD/RELEASE`  
- Mais lento para criar o projeto; mais rápido/estável para materializar depois  
- Exemplos: drone, arma composta, exoesqueleto parcial, ponte, kit médico  

**Regra:** quanto mais completo o item, mais o Soft Compile falha.  
Pensar “tanque” não cria tanque. **Programar** o tanque (dias/semanas + módulos + energia absurda) pode.

## Materialização — checklist

Toda build:
1. Custo energético (burst + hold)  
2. Tempo de compilação  
3. Dificuldade (compreensão × dados × complexidade)  
4. Risco (falha, matéria instável, dano)  

### Progressão de objetos (escala lenta)

| Fase | O que | Modo | Visual |
|------|-------|------|--------|
| T1 início | Peças, ferramentas | Soft | Quase mundano |
| T1 meio/fim | Defesa, híbridos | Soft→Hard proto | Veios digitais |
| T2 | Armas/dispositivos salvos | Hard + Biblioteca | Fase Hélice clara |
| T3 | Drones, armadura parcial | Hard + módulos | Aura digital plena |
| T4+ | Estruturas, veículos, “qualquer coisa” modelável | Domínio | Assinatura máxima |

**Regra de compreensão:** sem modelo, sem build.  
Copiar exige estudo. Inventar exige projeto.
